# ADR-0001: Universal Industrial Line Designer first, PLC read-only later

**Статус:** Proposed / на ревью  
**Дата:** 2026-11-13  
**Контекст:** один продукт для бетонных заводов и родственных производств, с возможностью разных PLC.

## Проблема

Написание полностью кастомной SCADA для одного контроллера привязывает продукт к OEM, ускоряет накопление технического долга и несёт повышенные эксплуатационные риски. Однако попытка создать полноценную «универсальную SCADA + PLC IDE + MES + ERP» сразу неуправляема.

## Решение

1. Продуктовая основа — универсальный Engineering Line Designer с версионированным Equipment Catalog, typed ports и material-flow validation; concrete batching — первый sector profile.
2. Разделить topology/layout, signal mapping, production recipes и procedural control.
3. React + TypeScript + React Flow для редактора; Java 21 / Spring Boot MVC / PostgreSQL для серверной части; независимый Industrial Edge для OPC UA/Modbus.
4. Локальная PLC логика и safety-системы автономны; любые промышленные протоколы R2 — read-only, по умолчанию отключены.
5. Начать с детерминированного симулятора, затем квалифицировать live read-only на одном PLC; командное управление — только отдельное утверждённое ТЗ.
6. Разработка на рабочей ветке с тест-first и Draft PR; main сохранять стабильным.
7. Модульный монолит, затем выделение сервисов только при наблюдаемых границах масштабирования/надёжности.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана как первая |
|---|---|
| Сразу заменить PLC + HMI | риск безопасности, отсутствует проверенная инженерная компетенция и доступ к стенду |
| Только дашборд телеметрии | не формирует универсальную доменную модель линии |
| Сразу микросервисы / Kafka | избыточная стоимость и эксплуатационная нагрузка на старте |
| Привязка к одному Siemens/ОВЕН | лишает обещанной мультивендорности |
| Только frontend без серверных ревизий | недостаточна прослеживаемость для multi-user engineering |

## Последствия

Плюсы: переносимость каталога, независимое тестирование без оборудования, контролируемая стоимость и безопасность. Минусы: потребуется реальная работа с картами регистров/сертификатами и инженерная экспертиза, будущий commissioning может потребовать OEM-specific адаптеров.

## Признаки пересмотра

Первые реальные объекты используют недоступные по сети протоколы; промышленный инженер отклоняет портовую модель; не достигаются SLO интерфейса; другой стандарт безопасности обязателен по конкретной юрисдикции. Тогда новое ADR с trade-off и migration plan.
