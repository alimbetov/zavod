# Smart Equipment Library — первый функциональный срез R0

**Статус:** Draft / экспериментальная доменная библиотека на Java 21. Требования и ревью: [R0 master specification](../ZAVOD-MASTER-SPEC.md).

## Что реализовано

- 15 неизменяемых шаблонов оборудования; 2 профиля: `batch.concrete.v1` и `continuous.pump.v1`.
- `EquipmentType`: версия, видимые метаданные, `Capability`, `Mode`, физические `Port`.
- Порты имеют стабильный ключ, направление, среду и min/max кратность подключения.
- Смеситель `batch-mixer` имеет **раздельные** порты `water-in` и `admixture-in`.
- `ConnectionRules` проверяет базовую совместимость `OUT → IN` и совпадение среды.
- `IndustryProfile` выбирает доступное оборудование для конкретного профиля линии, не навязывает профиль всей площадке.

**Рецепт не хранится внутри EquipmentType:** режим `RECIPE_PARAMETERS` только сообщает о возможности использовать параметры производственного рецепта. Само описание, версия и утверждение рецепта — будущий MES-домен.

## Как проверять

Из корня репозитория с JDK 21:
```bash
bash scripts/test-catalog.sh
```
18 smoke-проверок используют только JDK; есть GitHub Actions `catalog-smoke` для их выполнения. Переход на JUnit 5/Maven и расширенная интеграционная квалификация — отдельный этап; smoke CI не делает систему production-ready.

## Что сознательно НЕ реализовано

Нет интерфейса React, связи экземпляров оборудования в графе, проверки заполнения портов на уровне линии, хранения Plant/Line в PostgreSQL, реальных PLC-сигналов, рецептного движка, выдачи команд, симуляции и сертификатов промышленной безопасности.

## Следующий вертикальный сценарий

`Create Line → select Profile → add Equipment → connect Ports → Validate → Save/Export JSON → Reopen`.

Сначала импортировать и проверить исторический React R0.1, затем подключить к нему контракт каталога через versioned API/DTO. Java domain станет авторитетом на сервере, а UI получит клиентскую проверку для подсказок. Пока отдельный frontend не импортирован, запуск графического редактора не входит в этот PR.

## Ограничение совместимости

Ключи текущего Java-каталога и старого R0.1 JSON необходимо сопоставить через явную таблицу migration/adaptation; обещания «прямой совместимости» нет. Схема экрана не является физической топологией, а тег PLC не является ID физического порта.
