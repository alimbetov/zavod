# Zavod IndustrialOS — стратегия SCADA + MES (2026)

**Статус:** DRAFT, дополнение к [единому мастер-ТЗ](../requirements/R0-master-spec.md), не отдельная конкурирующая версия требований.  
**Дисциплина:** R0 Designer → R1 engineering backend → R2 read-only SCADA → R3 MES → R4 независимая квалификация ограниченных команд.

## Продуктовая цель

Превратить **Zavod Line Designer** в локально развёртываемую промышленную платформу для небольших и средних предприятий с существующими контроллерами. Главная ценность: **спроектировать технологическую линию → подключить теги без переписывания PLC → видеть состояние производства → получить достоверный журнал партий и расхода материалов**.

Не позиционировать R0 как готовую SCADA, MES или сертифицированную систему управления. Первая отрасль — бетонные узлы; новые отрасли создаются через пакеты оборудования/технологии и отдельную квалификацию.

## Различие трёх продуктовых модулей

| Модуль | Вопрос клиента | Конечный артефакт |
|---|---|---|
| Zavod Designer | Из каких компонентов и соединений состоит линия? | Утверждённая ревизия инженерной модели |
| Zavod SCADA | Что происходит с оборудованием сейчас и какие есть тревоги? | Live HMI, сигналы с качеством/временем, historian, журнал alarms |
| Zavod MES | Что было заказано, сколько произведено и из чего? | Заказ, версия рецепта, batch record, расход/отклонения/отчёт смены |

Технологически это **три модуля на одном инженерном registry**, а не три отдельные несвязанные программы.

## Позиционирование относительно рынка

Ignition уже предоставляет готовую расширяемую SCADA/IIoT-платформу, а связанные MES-модули Sepasoft решают производственный учёт. Поэтому прямое соревнование по количеству драйверов, универсальных виджетов или готовых интеграций — плохая стратегия для маленькой команды.

Узкая ниша Zavod:
1. **Retrofit-first:** подключаем существующее оборудование, не заставляем менять исправный PLC.
2. **Concrete batching first:** типовые узлы, рецептуры, весовые дозаторы, фактические партии и отклонения.
3. **Engineering-led configuration:** сначала доказуемо валидная топология/порты/сигналы, потом HMI.
4. **On-premise-first:** завод работает без интернета и без SaaS-бэкенда.
5. **Прозрачный производственный учёт:** связываем recipe version, измерения и batch record, вместо ручных Excel-отчётов.
6. **Казахский, русский и английский** для интерфейса на первом рынке при сохранении нейтральных единиц измерения.

Это гипотеза позиционирования, а не доказанная оценка спроса. Перед платной разработкой провести 5–10 интервью с владельцами/инженерами заводов.

## Архитектурное направление

- **React + React Flow** для Desktop/Web инженерного редактора и HMI.
- **Java 21 + Spring Boot modular monolith** для пользователей, ревизий, каталога, рецептов, партий, аудита.
- **PostgreSQL** для проектных и производственных данных, historian начинается с обычной БД и развивается по измерениям.
- **Отдельный локальный Edge** — OPC UA (Eclipse Milo) и Modbus TCP, чтение сигналов, quality, retry, durable queue.
- **MQTT/Sparkplug B** для распределённых площадок позднее, не обязательная инфраструктура MVP.
- **PLC остаётся авторитетом управления**, safety interlocks и независимое управление двигателями/клапанами только в промышленных контроллерах.
- **Cloud/Fleet** — дополнительный контур аналитики с исходящим контролируемым потоком, без прямого удалённого управления PLC.

## Два принципиальных процесса

### Engineering Change Control
`DRAFT → REVIEW → APPROVED → ACTIVE → SUPERSEDED/ARCHIVED`

Запрет активации без проверки обязательных соединений, прав, миграций и тестовой валидации. Действующая ревизия и ревизия, использованная при партии, неизменяемы.

### Batch Traceability
`ProductionOrder → ApprovedRecipeVersion → PLC Batch Events → ActualMeasurements → BatchRecord → MaterialReconciliation`

При обрывах связи учитываем качество данных и неполные партии явно, а не додумываем их статусы в MES. Номинальные и фактические дозы хранятся отдельно.

## Где остановиться на каждой ступени

- **R0/R1:** работающий конструктор + серверное хранение. Ценность: инженерная документация и подготовка конфигурации.
- **R2:** полноценный **read-only SCADA-monitoring pilot** параллельно действующему HMI. Ценность: видимость и история.
- **R3:** **MES batching pilot** на одном заводе. Ценность: traceability и экономия ручного учёта.
- **R4:** **контролируемые supervisory commands** только при отдельном GO после PLC/safety risk assessment и FAT/SAT. Это не просто feature flag.
- **R5:** multi-plant аналитика и новые отраслевые пакеты.

## Метрики успеха для первого пилота

- Время подключения от списка сигналов до первого HMI.
- Доля партий с полным и непротиворечивым batch record.
- Сходимость отчётов Zavod с проверенными журналами и калиброванными весами.
- Время ручного заполнения отчётности за смену «до/после».
- Время обнаружения потери/устаревания сигнала.
- Ноль неразрешённых записей в PLC и подтверждённая автономность control loop.

Численные SLO/ROI определяются после пилота, не объявляются достигнутыми.
